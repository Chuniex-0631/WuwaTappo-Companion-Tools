# 自动挂机 1.1.1：状态与闭环

本说明基于 Wuwa Tappo 1.0.2 副本内提取的前端代码，以及共用状态机的离线场景测试。
桌宠版本升级后，控件布局或显示规则可能变化。

AutoPilot 1.1.1 与 Toolkit 1.5.1 共用槽位识别、操作等待及逐槽退避逻辑。
AutoPilot 自动补点至 2000 点；Toolkit 的监控模式不会自动补点，见 [TOOLKIT.md](TOOLKIT.md)。
两款工程均编译 `src/Shared/` 中的同一份槽位读取和控制器源码，避免分别维护时产生行为差异。

## 可见状态不等于底层状态

正常登录并完成同步时，原桌宠的显示条件为：

| 点数余额 | 槽位显示 |
| --- | --- |
| 小于 1000 | 两槽隐藏，“始终显示宝箱”也不能覆盖点数门槛 |
| 1000～1999 | 只展示一个槽位；原程序 left 槽到期时优先展示 left，否则选 right |
| 至少 2000 | 两槽均可展示；未到期的倒计时还受“始终显示宝箱”或悬停条件影响 |

工具按屏幕几何区分上、下槽位，不依赖原程序 left/right 命名。
界面上的“空/隐藏”仅表示未发现该槽位的可见控件，不能证明没有冷却或待领取宝箱。

## 状态机

| 观察结果 | 动作 | 后续入口 |
| --- | --- | --- |
| 窗口/点数不可读取，或读取超时 | 停止 F24，等待恢复 | 下一轮读取 |
| 宝箱按钮禁用/处理动画中 | 暂停输入与新点击 | 下一轮读取 |
| 可用余额至少 1000，出现可点击宝箱 | 停止连点，复核同一槽位及位置，鼠标空闲后点击一次 | 等待响应 |
| 点击后不足 1000，两槽隐藏 | 至少等待 2 秒及两次稳定槽位变化，结束当前等待 | 按新余额补点 |
| 点击后 1000～1999，原槽隐藏、另一槽可领取 | 结束当前等待，重新选择可见宝箱 | 领取另一槽 |
| 点击后原槽进入倒计时 | 连续观察变化后结束当前等待 | 补足储备或等待 |
| 点击后原宝箱持续可见/忙碌 | 最多等待 12 秒，然后按该槽位退避 | 有其他宝箱时允许先处理另一槽 |
| 无可领取按钮，余额不足 2000 | 有限批次补点 | 每轮重读余额与槽位 |
| 无可领取按钮，余额至少 2000 | 停点，等待冷却或显示更新 | 下一轮读取 |
| 补点期间 12 秒余额没有变化 | 停点 30 秒，再尝试 | 重新读取后有限补点 |
| 用户停止/关闭 | 使旧任务失效并释放 F24 | 仅手动开启后恢复 |

## 为什么不再统计领取数量

原桌宠在领取响应后会先设置一个本地预测倒计时，再校验消费点数及处理奖励信息。
因此“出现倒计时”不等于已经独立证明背包资产到账。两款工具均不再累计领取次数，
也不把按钮消失称为领取成功；它只将稳定的界面变化用于结束当前事务、继续规划。
最终奖励以桌宠背包和账号侧结果为准。

## 双槽储备

补点目标固定为 2000 点余额。可见宝箱的领取优先于补点；只有可领取按钮不存在时
才补足储备。这个保守策略能处理被余额门槛隐藏的第二槽，也无需猜测隐藏倒计时。
计数是领取消耗余额，不能按累计值每跨过一个千点推断产生宝箱。
本版不新增模拟输入来维持倒计时，也不修改原桌宠的计时规则。

## 并发与恢复

- 控制器仅在 UI 线程更新，读取和点击在后台执行；UIA 读取绑定本轮选定的桌宠进程。
- 点击前复核桌宠进程、输入窗口、余额、目标槽位及两槽忙碌状态。禁用按钮不会被同位置的倒计时覆盖。
- 每次开始/停止使用独立代数校验，旧任务不会启动新一轮连点。
- F24 按有限数量发送，每轮授权最多持续 3 秒；读取卡住后也会自动停止。
- 输入发送与停止使用同一把锁；停止后等待旧 F24 线程退出，释放按键。
- 鼠标按下与抬起合并发送；部分发送失败时补发抬起，减少停止或退出时的输入竞态。
- 每次 UIA 等待最多 2 秒，最多保留两个未完成读取，防止任务无限累积。
- UIA 恢复后丢弃过期结果；桌宠重启可使用另一条有界读取任务重新连接。
- 若第三方 UIA 提供方永久卡死且两个任务名额均被占用，输入保持暂停；退出并重开
  助手可清除该提供方挂起状态。工具不会尝试终止桌宠或修改账号状态。

## 离线测试

```powershell
./scripts/build.ps1 -Test
```

脚本分别针对两款程序编译并运行回归测试。状态机测试回放点数和槽位快照；界面识别测试使用捕获值，输入测试使用替代发送接口，生命周期测试操作测试窗口。按钮交互测试对实际按钮类回放鼠标/F24 事件交错，验证点击及键盘触发。不登录账号、不发网络请求、不发送真实键鼠输入。覆盖和结果见 [v1.2.1 验证记录](VALIDATION-v1.2.1.md)。

工具本身只读取本机界面并发送输入；桌宠本体的登录与领取仍使用它自己的网络流程。

## 托盘与退出

补点期间也可点击“−”隐藏到系统托盘，自动挂机继续；双击托盘或选择“显示主窗口”恢复。托盘“停止全部操作”会停止挂机但保留程序，X、Alt+F4 和托盘“退出”会停止操作并退出。重新启动程序后需手动开启挂机。

两款新版助手共用会话互斥，重复启动任一款会恢复当前工具；切换前先退出当前工具。启动时也会检查旧版占用，升级前请先退出两款旧版助手。托盘图标被收纳时，可从 Windows 通知区域展开，或再次打开 EXE 恢复窗口。

## 1.1.1 按钮交互修复

合集 v1.2.0 曾将按钮改为标准 Click，但未隔离持续补点产生的 F24 键盘事件。若 F24 释放发生在按钮的鼠标按下与释放之间，WinForms 会清除按下标记，最小化或停止按钮可能因此没有反应。这不是禁止补点期间最小化的设计。

本版与 Toolkit 共用 `F24SafeButton`，只过滤按钮收到的 F24 KeyDown/KeyUp，保护窗口和功能按钮；Space/Enter、标准 Click 与辅助功能触发继续使用正常按钮语义。补点输入仍发送给桌宠，最小化不会停止补点。

v1.2.0 的生命周期测试没有覆盖这类真实按钮事件交错，本版新增对应回归；历史验证记录保留原范围。
