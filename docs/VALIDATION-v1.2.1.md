# v1.2.1 验证记录

日期：2026-11-17。对应 **Toolkit 1.5.1** 和 **AutoPilot 1.1.1**。

## 本次问题与覆盖缺口

用户反馈 AutoPilot 补点期间点击最小化无效。检查确认持续 F24 释放事件会清除 WinForms 按钮的鼠标按下状态；v1.2.0 改用标准 Click 后，鼠标按下与释放之间插入 F24 会使点击丢失。此行为并非产品设计。

v1.2.0 的生命周期测试覆盖托盘控制器和窗体生命周期，但直接调用相关方法，未覆盖实际按钮的鼠标/F24 事件交错。旧版的 3187 项断言不能证明该交互路径已经通过验证。[v1.2.0 验证记录](VALIDATION-v1.2.0.md) 按原范围保留。

本版新增共用 `F24SafeButton`，只过滤按钮收到的 F24 KeyDown/KeyUp，保护两款应用的窗口按钮与功能按钮；正常 Click、Space/Enter 和辅助功能入口保留。问题机制可参照微软维护的 [ButtonBase 源码](https://github.com/dotnet/winforms/blob/main/src/System.Windows.Forms/System/Windows/Forms/Controls/Buttons/ButtonBase.cs) 中 `OnKeyUp` 对按下状态的处理；本机 .NET Framework 按钮事件调用也复现了 F24 释放清除该标记。

## 验证方法

- **新增按钮交互回归**：对实际窗口按钮和功能按钮类调用其事件处理路径，回放鼠标按下、F24 按下/释放、鼠标释放；检查正常点击、Shift/Ctrl/Alt 修饰键、空格期间插入 F24、Enter 和辅助功能默认操作。实际窗体的最小化按钮经过窗口消息路径触发后隐藏，模拟补点线程保持运行且发送计数继续增长；随后停止全部操作，确认没有继续发送。测试不发送全局 F24，不触碰桌宠进程；保留标准辅助功能入口不等于已经通过真实辅助技术客户端实测。
- **状态机与界面解析**：继续使用离线快照，覆盖低余额隐藏、双槽、忙碌、不可读状态、超时退避、点数停滞与读取几何边界。
- **输入发送**：以替代发送接口覆盖完整、拒绝与部分发送及抬起补偿，不产生真实键鼠输入。
- **生命周期**：使用测试窗体检查隐藏、恢复、停止、退出及资源清理。
- **AutoPilot 工作线程**：使用替代输入接口检查有限补点预算、输入租期、旧任务失效、发送失败及停止边界。

对 v1.2.0 两款源码分别编译同一新测试，均在鼠标按下状态保留检查中失败；v1.2.1 两款均通过。此次按钮交互测试补充的是原先未覆盖的事件交错。它与实际桌宠运行中的全局输入和奖励流程不同，不将后者记为已经实测。

## 使用与恢复

- 最小化后已经开启的补点、计数或监控继续运行；停止和退出应分别通过对应入口执行。
- 托盘图标可能被收纳；可展开 Windows 通知区域，或再次启动新版 EXE 恢复当前窗口。
- 升级前先退出旧版。若旧版的鼠标按钮受持续 F24 干扰，可使用 Alt+F4 退出。
- UIA 读取无法可靠恢复时暂停操作；提供方永久挂起并占满两个读取名额时，可退出并重新启动助手。程序不会终止或修改桌宠进程。
- 实际奖励仍以桌宠背包和账号记录为准。
